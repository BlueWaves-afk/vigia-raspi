# BNO085 IMU (Bosch Sensortec / CEVA)

**Interface:** SPI0 on Pico 2 @ 3.0 MHz (CPOL=1 CPHA=1 = Mode 3)  
**Pins:** SCK=GP18, MOSI=GP19, MISO=GP16, CS=GP17, INT=GP20, RST=GP21, WAKE=GP22  
**Data Rate:** 100 Hz quaternion + linear acceleration (NDOF fusion mode)

## Sensor Fusion Mode
**NDOF** (Nine Degrees of Freedom) fusion mode — produces calibrated unit quaternion representing orientation relative to Earth frame. Required for gravity compensation in [[fusion-node]].

## Output Reports Used
| Report ID | Report Type | Rate | Q-point |
|---|---|---|---|
| 0x05 | Rotation Vector | 100 Hz | Q14 (1/16384.0 scale) |
| 0x04 | Linear Acceleration | 100 Hz | Q8 (1/256.0 scale, m/s²) |

## Data Fields (after Q-point conversion)
- `q_w, q_x, q_y, q_z` — unit quaternion (world←body orientation)
- `lin_accel_x/y/z` — body-frame linear acceleration in m/s² (gravity INCLUDED)
- `calibration_status` — 0=uncal, 3=fully calibrated

## Gravity Compensation (Pi-side, [[fusion-node]])
The BNO085 outputs raw accelerometer data WITH the 1g gravity component. The Pi performs gravity subtraction using the quaternion:
```
a_world = q * a_body   (quaternion sandwich)
a_detrended = a_world - [0, 0, 9.81]
ISS = |a_detrended.z| / max(v_GPS, 2.0 m/s)
```
See [[adr-gravity-compensated-iss]].

## Communication via Pico 2
- BNO085_INT (GP20) falling edge → DMA SPI0 transfer (512 bytes) → parse SHTP frame
- Data available to Pi via [[cobs-usb-cdc]] → [[sensor-bridge-node]] → `/vigia/imu` topic
